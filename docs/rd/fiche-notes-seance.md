# Fiche de notes — séance d’essai d’usage

**Un seul formulaire par observation, sans nom, sans diagnostic, sans donnée personnelle.**
Protocole de référence : [`protocole-essais-usage.md`](protocole-essais-usage.md). Cette fiche en est le support papier, pas un protocole distinct.

> **Avant d’écrire :** la personne a donné son accord pour cette observation, elle sait qu’elle peut arrêter à tout moment, et elle a pu demander qu’une note ne soit pas gardée. Si ces trois conditions ne sont pas réunies, ne rien écrire.

---

## 1. Contexte de la séance

| Champ | À remplir | Pourquoi c’est demandé |
|---|---|---|
| Date | | Situer la version du site essayée |
| Version du site | `git describe --tags` ou la date du dernier commit affiché | Un obstacle corrigé depuis ne doit pas être reconduit |
| Page de départ | | Reproduire la séance |
| Largeur d’écran approximative | 320 / 390 / 768 / 1 024 / 1 440 px | Une barrière peut n’exister qu’à une largeur |
| Zoom du navigateur | 100 % / 150 % / 200 % / autre | Ne pas confondre un défaut de zoom avec un défaut de mise en page |
| Mode d’accès | *au choix de la personne, décrit en un mot si elle le souhaite* : clavier seul, lecteur d’écran, contacteur, souris, tactile | Le contexte d’accès change ce qu’on observe |
| État de départ appliqué | `profil-demonstration.mjs` → état : … | L’état de départ doit être reproductible |

**Ne pas écrire :** nom, âge exact, adresse, employeur, école, diagnostic, nom d’un handicap, situation financière, contenu saisi dans un exercice, adresse IP, identifiant de session.

**Résultat « avec aide »** : la personne a réussi après une intervention du facilitateur. Ce n’est ni un échec de la personne, ni une réussite de l’interface — c’est le signe que l’aide doit être intégrée au site.

## 3. Ce qui a été dit, sans être interprété

Noter les mots de la personne sur *l’interface*, pas sur elle-même. Une phrase vaut mieux qu’une note d’ambiance.

| Ce qu’elle a dit (mots proches) | Sur quel élément | Ce que ça peut vouloir dire pour la conception |
|---|---|---|
| | | |
| | | |

**Ne pas écrire :** « elle n’a pas compris », « il est dyslexique », « elle se débrouille mal ». Écrire : « le mot “repères” n’a pas été relié au contour de focus », « le bouton a été cherché hors du panneau ».

---

## 4. Obstacles classés

Cocher la catégorie — une seule par ligne, la plus proche.

- [ ] **Contenu** : le texte est faux, ambigu ou manquant.
- [ ] **Terme** : le mot est correct mais incompris dans ce contexte.
- [ ] **Navigation** : la personne ne trouve pas où aller.
- [ ] **Technique** : une commande n’a pas répondu.
- [ ] **Accessibilité** : le focus, le nom ou l’état n’était pas perceptible.
- [ ] **Consigne** : la tâche elle-même était mal formulée par le facilitateur.

La dernière catégorie existe pour éviter de faire porter à l’interface une faute de la séance.

## 7. Ce que cette fiche ne fait pas

Elle ne remplace pas un consentement écrit quand le cadre l’exige. Elle ne vaut pas validation d’accessibilité, ni RGAA, ni WCAG. Elle ne mesure ni la compréhension, ni l’apprentissage, ni l’efficacité d’une personne. Un petit nombre d’observations ne fait pas un taux, une moyenne ou une population.

**Une seule observation peut révéler une barrière grave** — elle justifie une correction immédiate, pas une généralisation.
