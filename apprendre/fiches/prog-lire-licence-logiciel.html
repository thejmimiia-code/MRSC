Fiche autonome · Informatique et programmation

Lire une licence avant de réutiliser un programme

Repérer s’il existe une licence, ce qu’elle autorise de façon générale, et ce qu’il faut encore vérifier avant de copier un programme.

Informatique et programmationRepère 2 · consolider9 minutes environHorizon du contenu : Premiers repères sur le code visible, la licence et l’attribution ; aucun conseil juridique personnaliséStatut éditorial : Prototype à relire

État éditorial : Brouillon pour distinguer le fait de voir un code et le droit de le réutiliser. Faire relire par une personne compétente en propriété intellectuelle du logiciel. L’exemple de notice est fictif ; la fiche ne choisit pas de licence pour un projet réel. Sources, droits, accessibilité et essais apprenants restent à contrôler.

Repère, pas étiquette : Relier des notions et s’entraîner dans de nouveaux exemples. Tu peux essayer la fiche sans prérequis, demander de l’aide ou choisir une autre matière.

Ce que tu vas essayer

Dans un exemple fictif, séparer « le code est lisible », « une licence décrit des usages » et « je peux m’en attribuer la création ».

Une situation de départ

Notice fictive jointe à un petit script « horloge-exemple » : « Vous pouvez copier et modifier ce script si vous indiquez « horloge-exemple » comme origine. Vous ne pouvez pas prétendre l’avoir créé. » Un camarade dit : « Puisque le fichier est public, on peut le coller dans notre projet sans rien écrire. » Que vérifier ?

Analogie du quotidien

Comme une recette affichée en vitrine, avec une étiquette d’usage

Voir une recette collée sur une vitrine ne dit pas si on a le droit de la republier sous son nom. L’étiquette (sur place, à emporter, citer le restaurant) précise l’usage. Une licence joue un rôle comparable pour un programme : elle décrit des permissions et des limites, quand elle existe.

Limite de l’image : Une recette n’est pas un logiciel : les règles de droit, les copies, les combinaisons de licences et les obligations de source sont spécifiques. Une étiquette de restaurant n’explique ni un contrat, ni un pays, ni une version de licence.

Quelques mots utiles

  • Code source — forme du programme destinée à être lue et, souvent, modifiée par une personne.
  • Licence — texte qui indique ce que l’on peut faire du programme (copier, modifier, partager) et à quelles conditions.
  • Attribution — indiquer l’origine ou les auteurs demandés par la licence, sans s’en attribuer la création si c’est interdit.
  • Tous droits réservés — en l’absence d’autorisation, le simple fait qu’un fichier soit visible ne suffit pas à autoriser la copie.
  • Identifiant de licence — nom court parfois utilisé pour désigner un texte connu ; il faut encore lire le texte applicable.

Une méthode possible

  1. Cherche un fichier ou une notice de licence près du programme (LICENCE, README, en-tête de fichier).
  2. Lis ce qui est autorisé, ce qui est interdit, et s’il faut citer une origine.
  3. Sépare trois idées : voir le code ; avoir une permission écrite ; revendiquer la paternité.
  4. Si la notice manque, est floue ou mélange plusieurs textes, ne copie pas : demande à une personne compétente ou laisse le fichier de côté.
  5. Cette fiche n’identifie pas la licence d’un projet réel et ne remplace pas un conseil adapté.

À toi d’essayer

D’après la notice fictive de « horloge-exemple », laquelle de ces actions est cohérente avec le texte donné ? A) Coller le script dans un autre projet sans mentionner l’origine. B) Le modifier pour un usage interne en indiquant « horloge-exemple » comme origine. C) Dire que tu as créé le script toi-même.

Afficher une aide

Relis les deux phrases de la notice : l’une parle de copier/modifier avec une origine, l’autre interdit de prétendre l’avoir créé.

Afficher une correction possible
  1. B est cohérente avec la notice fictive : copier ou modifier est mentionné, à condition d’indiquer l’origine « horloge-exemple ».
  2. A oublie l’attribution demandée dans l’exemple. C contredit l’interdiction de s’en attribuer la création.
  3. Même B resterait à vérifier dans un cas réel : version du texte, territoire, combinaisons avec d’autres programmes, et ce que « usage interne » recouvre. Cette notice n’est pas une licence connue.

La correction montre un chemin possible. Pour un calcul, vérifie aussi chaque étape et le résultat.

Pour retenir

  • Un fichier public n’est pas automatiquement libre de copie.
  • On lit la licence avant de réutiliser, pas après.
  • Citer l’origine n’est pas la même chose que s’attribuer la création.
  • En cas de doute, on s’abstient plutôt que d’inventer une permission.

Et dans une autre situation : Cette lecture peut servir avant d’emprunter un script, une bibliothèque ou un exemple trouvé en ligne. Pour publier un projet ou combiner plusieurs licences, consulte les textes applicables et, si besoin, une personne compétente ; cette fiche n’est pas un avis juridique.
