Fiche autonome · Informatique et programmation

Distinguer une table, une requête et une page Web

Repérer où les données sont rangées, quelle question on leur pose, et ce qu’une page Web montre — sans confondre les trois.

Informatique et programmationRepère 2 · consolider9 minutes environHorizon du contenu : Premiers repères sur le stockage structuré et l’affichage Web ; aucun langage de requête ni aucun serveur n’est enseignéStatut éditorial : Prototype à relire

État éditorial : Brouillon d’informatique pour séparer une table de données, une question posée à ces données et une page qui affiche un résultat. Faire vérifier les termes par une personne compétente en bases de données et en Web. L’exemple est fictif ; la fiche n’enseigne ni SQL, ni API, ni configuration. Sources, droits, accessibilité et essais apprenants restent à contrôler.

Repère, pas étiquette : Relier des notions et s’entraîner dans de nouveaux exemples. Tu peux essayer la fiche sans prérequis, demander de l’aide ou choisir une autre matière.

Ce que tu vas essayer

Nommer, dans un exemple fictif, la table, la requête et le résultat affiché, et dire ce que la page ne contient pas forcément.

Une situation de départ

Club fictif « Atelier des cartes ». Un tableau interne liste prénom, jour et activité. Sur le site du club, une page affiche : « Mardi : 3 personnes en dessin ». D’où vient ce « 3 » ?

Analogie du quotidien

Comme un classeur, une question au secrétariat, et un tableau d’affichage

Le classeur range les fiches. Une question au secrétariat (« qui vient mardi en dessin ? ») ne copie pas tout le classeur. Le tableau d’affichage montre un résumé utile, pas forcément toutes les fiches. Table, requête et page Web jouent des rôles comparables : ranger, demander, montrer.

Limite de l’image : Une base réelle peut être répartie, protégée, mise à jour en continu. Une page Web peut cacher, filtrer, arrondir ou dater un résultat. Le secrétariat d’un club n’explique ni les droits d’accès, ni les formats d’échange, ni les pannes réseau.

Quelques mots utiles

  • Table — ensemble de lignes décrites par les mêmes colonnes, par exemple prénom, jour, activité.
  • Requête — question précise posée aux données, avec un critère : un jour, une activité, un compte.
  • Résultat — lignes ou nombre obtenus après la question ; ce n’est pas automatiquement tout le contenu de la table.
  • Page Web — document affiché dans le navigateur ; elle peut montrer un résultat sans être le lieu de stockage.
  • Échange — le navigateur demande une ressource à un serveur ; la réponse peut être une page, pas la table entière.

Une méthode possible

  1. Repère d’abord ce qui est stocké : quelles colonnes, pour quel usage, dans l’exemple fictif.
  2. Formule la question réellement posée : filtrer, compter, lister ? Ce n’est pas la même chose que « tout voir ».
  3. Regarde ce que la page affiche : un nombre, une liste, une date ? Note ce qui n’apparaît pas (noms, autres jours, source).
  4. Sépare les trois rôles : rangement, question, affichage. Une page à jour n’est pas une preuve que la table est complète.
  5. Pour une donnée réelle, vérifie aussi l’émetteur, la date et les conditions d’accès ; cette fiche ne les enseigne pas.

À toi d’essayer

Dans la situation fictive, identifie : 1) un exemple de table, 2) une requête possible qui aboutit au « 3 », 3) ce que la page ne montre pas. La table inventée contient : Léa / mardi / dessin ; Noé / mardi / dessin ; Inès / mardi / dessin ; Paul / mercredi / théâtre.

Afficher une aide

Le « 3 » correspond à un compte, pas à une liste de prénoms. Cherche le critère commun (jour et activité), puis ce qui reste dans la table hors de ce critère.

Afficher une correction possible
  1. Table fictive : quatre lignes avec les colonnes prénom, jour, activité.
  2. Requête possible : compter les lignes dont le jour est mardi et l’activité est dessin. Le résultat numérique est 3.
  3. La page montre ce nombre ; elle ne montre pas les prénoms, ni la ligne de mercredi, ni le classeur entier. D’autres requêtes donneraient un autre affichage.
  4. L’exemple n’utilise aucun langage de requête réel. Sur un site, l’affichage peut aussi être ancien, arrondi ou limité par des droits d’accès.

La correction montre un chemin possible. Pour un calcul, vérifie aussi chaque étape et le résultat.

Pour retenir

  • Ranger, demander et afficher sont trois opérations distinctes.
  • Une page Web n’est pas la base : elle en montre un extrait ou un résumé.
  • Changer la question change le résultat, même si la table reste la même.
  • Un chiffre affiché n’indique ni la qualité des données, ni qui a le droit de les voir.

Et dans une autre situation : Cette distinction aide à lire un tableau de bord, un catalogue de données ou un résultat de recherche. Pour interroger une vraie base ou publier des données, il faut les outils, les droits et la documentation du jeu concerné ; cette fiche n’enseigne ni langage ni procédure.
